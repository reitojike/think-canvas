# 機能仕様: Canvas Foundation

**対象 Issue**: [#2 Canvas Foundation](https://github.com/reitojike/think-canvas/issues/2)
**作成日**: 2026-09-26
**状態**: 設計確定
**入力**: PRD を要求の authority とし、HTML モックを操作・見た目の参考実装として参照する。どちらも公開リポジトリには含めない。

## Clarifications

### Session 2026-09-26

- **座標**: 要素の配置はボードの世界座標として保持し、パン・ズーム時は表示変換だけを変更する。画面倍率や端末サイズ変更で配置の意味を失わないため。
- **編集終了**: 「完了」は空白以外の Draft を確定し、「キャンセル」は未確定の変更を破棄する。空白の新規 Draft は要素を作らない。既存要素の空白編集は確定しない。
- **保存タイミング**: 作成・編集・移動および Undo/Redo の確定直後に端末内保存へ反映する。パン・ズーム・選択は保存しない。
- **保存完了**: 画面上の確定操作は保存完了まで進行中として扱う。保存に失敗した場合は未保存を明示し、同じ状態を再試行できるようにする。
- **Undo 境界**: 履歴は起動中の最大 80 操作とし、再起動後は空にする。確定済み要素の状態は再起動後も残す。

## 利用シナリオと受け入れ条件

### ユーザーストーリー 1: 思考をその場に書き残す (優先度: P1)

利用者は最初のボードの空白をタップし、その位置に日本語のテキストを記録できる。書いた内容を後から選択して編集でき、タイトル・本文、墨色・朱色を切り替えられる。完了した内容はアプリを終了して再起動しても残る。

**単独検証**: 空白タップからテキストを作成・編集し、アプリ再起動後に内容、種類、色、位置を確認する。

**受け入れシナリオ**:

1. **前提** 空のボードが表示されている。**操作** 空白をタップして文字を入力し確定する。**結果** タップした世界座標にテキスト要素が現れる。
2. **前提** テキスト要素がある。**操作** 選択後に再度タップして内容、タイトル・本文、墨色・朱色を変更し確定する。**結果** 変更が表示と保存内容に反映される。
3. **前提** 確定済みの要素がある。**操作** アプリを完全に終了し再起動する。**結果** 同じボード上に内容、種類、色、位置が復元される。
4. **前提** 新規入力を開始した。**操作** 文字を入力せず閉じる。**結果** 空の要素は作成されない。

### ユーザーストーリー 2: 空間を見渡す (優先度: P2)

利用者はキャンバスを指で移動し、ピンチで拡大・縮小できる。指がテキスト上から動き始めても、通常のドラッグなら表示領域を動かせる。表示操作によって要素の世界座標や互いの位置関係は変わらない。

**単独検証**: 要素を配置したボードで空白・要素上からパンし、ピンチの前後で同じ配置に戻れることを確認する。

**受け入れシナリオ**:

1. **前提** ボード上に要素がある。**操作** 空白からドラッグする。**結果** 表示領域が移動し、要素の世界座標は変わらない。
2. **前提** 要素上に指を置いた。**操作** 長押しせずドラッグする。**結果** 表示領域が移動し、要素は移動しない。
3. **前提** ボードを表示している。**操作** 2 本指で拡大・縮小する。**結果** 指の周辺を基準に倍率が変わり、許容範囲 15～300% に収まる。

### ユーザーストーリー 3: 配置を直し、操作を戻す (優先度: P3)

利用者は要素を選択し、長押しドラッグで位置を変えられる。作成・編集・移動を Undo/Redo できる。パン、ズーム、選択は Undo の履歴に含まれない。

**単独検証**: 要素の作成、編集、移動を順に行い、Undo/Redo で各状態と保存結果を確認する。

**受け入れシナリオ**:

1. **前提** 要素がある。**操作** タップする。**結果** 要素が選択される。選択中に空白をタップすると選択だけが解除され、新規入力は始まらない。
2. **前提** 要素がある。**操作** 長押ししてドラッグする。**結果** 要素だけが移動し、移動後の世界座標が保存される。
3. **前提** 作成・編集・移動を確定した。**操作** 画面左下の Undo、続いて Redo を使う。**結果** 各操作の前後の状態に戻り、再適用される。使用不可時のボタンは無効表示になる。

### 境界条件

- 入力が空または空白文字のみの場合、確定しても要素を作らない。
- 編集を取り消した場合、確定済み内容を保持する。
- ドラッグ・ピンチが途中でキャンセルされても、要素や表示領域が不整合にならない。
- 保存時や再起動時に通信がなくても、確定済み要素を読み書きできる。
- 保存処理が中断・失敗しても、完了したと誤認させず、同じ変更を再試行できる。
- 日本語の長文、改行、文字サイズ設定の変更でも内容を読める。

## 要件

### 機能要件

- **FR-001**: 初回起動時に、利用可能な最初のボードを表示する。
- **FR-002**: 選択中の要素がない状態で空白をタップすると、その世界座標に新規テキスト入力を開始する。
- **FR-003**: テキスト要素は内容、タイトルまたは本文、墨色または朱色、世界座標を持つ。
- **FR-004**: 新規入力の空・空白のみの確定では要素を作らず、未確定の入力を取り消した場合も要素を作らない。
- **FR-005**: 要素のタップで選択でき、選択済み要素の再タップで編集できる。選択中の空白タップは選択解除のみを行う。
- **FR-006**: 長押しドラッグで要素を移動でき、通常の 1 本指ドラッグは開始位置が要素上でも表示領域をパンする。
- **FR-007**: 2 本指ピンチで表示倍率を 15～300% の範囲で変更できる。パン・ズームは要素の世界座標を変更しない。
- **FR-008**: 要素の作成・編集・移動を Undo/Redo できる。パン・ズーム・選択は操作履歴に含めない。
- **FR-009**: 確定済みのボードと要素を端末内に保存し、アプリ再起動後に復元する。保存完了までは進行中と示し、失敗時は再試行できる。基本操作にネットワーク接続を要求しない。
- **FR-010**: キャンバスは暖かみのある白を基調とし、日本語が読みやすい墨色と朱色を使う。操作ボタンのタッチ領域は 44dp 以上にする。
- **FR-011**: 要素を自動整列、スナップ、分類、再配置しない。AI による提案や変更は行わない。
- **FR-012**: 対象範囲のコンポーネントは HTML モックの視覚設計に準拠する。ボード名の小さなピル、中央の空ボード案内、選択中要素の朱色の枠と移動ハンドル、左下の Undo/Redo ピル、倍率表示、タップ位置のインライン入力とキーボード上の編集ツールバーを用いる。対象外の検索・ボード一覧・FAB 機能は追加しない。
- **FR-013**: GitHub CI で Android lint、ユニットテスト、デバッグビルド、公開情報境界チェックを実行する。
- **FR-014**: ボード名と操作 UI は、ステータスバー、画面の切り欠き、navigation bar に重ならず表示・操作できる。画面サイズや system bar の高さが変わっても、保存済み要素の世界座標は変更しない。

### 主要エンティティ

- **ボード**: 最初の作業空間。名前、更新時刻、配置された要素を持つ。
- **テキスト要素**: 内容、表示種別、色、世界座標を持つ独立した要素。
- **表示領域**: ボードを見る位置と倍率。要素の配置とは独立する。
- **操作履歴**: 確定済みの作成・編集・移動を戻す／再適用するための状態。

## 成功基準

- **SC-001**: 新規作成、再編集、タイトル・本文と色の切替を、各 10 回の手動試行ですべて完了できる。
- **SC-002**: 確定した要素の内容、種類、色、世界座標を、オフラインでの完全終了・再起動 10 回すべてで復元できる。
- **SC-003**: パン・ズームを各 10 回繰り返しても、保存された要素の世界座標が変化しない。
- **SC-004**: 作成・編集・移動の Undo/Redo を各 10 回試し、画面と再起動後の保存状態が期待どおりになる。
- **SC-005**: 空または空白のみの入力を 10 回閉じても、要素数は増えない。
- **SC-006**: 主要な操作ボタンはすべて 44dp 以上のタッチ領域を持ち、日本語の長文・改行を読める。
- **SC-007**: モックの対象コンポーネントについて、空状態・選択状態・編集中状態を Android 画面で照合できる。
- **SC-008**: PR head の GitHub CI で lint、ユニットテスト、デバッグビルド、公開情報境界チェックが成功する。
- **SC-009**: Android 実機でボード名、Undo/Redo、倍率表示、ツールが system bars と重ならず操作できる。

## 前提と範囲

- 最初のボードは自動作成する。複数ボードの作成・切替は対象外。
- Undo/Redo 履歴は起動中のセッションに限り、上限は 80 操作とする。ボード要素の確定状態は永続化する。
- 表示領域の位置・倍率はこの段階では再起動後の復元対象に含めない。
- 図形、矢印、複数選択、空間挿入、Ink、Semantic Zoom、検索、画像共有、AI は対象外。
- PRD の操作閾値は試作値として扱い、実機で使いやすさを確認して調整する。
