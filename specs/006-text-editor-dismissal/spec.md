# 機能仕様: テキスト入力の外側タップによる取り消し

**Feature Branch**: `codex/issue-71-text-dismiss`
**Created**: 2026-10-02
**Status**: Draft（merge までは現行仕様を置き換えない）
**Input**: [Issue #71](https://github.com/reitojike/think-canvas/issues/71)。現行 Canvas Foundation の編集終了契約と Board Lifecycle の保存契約を維持する。

## User Scenarios & Testing

### User Story 1 - 外側をタップして入力をやめる (Priority: P1)

利用者は、編集ツールバーまで指を移動せず、入力欄の外側を1回タップして未確定の入力を取り消せる。

**優先理由**: 日常の入力中断を短い操作で完了できる。
**独立した検証**: 空・文字ありの新規入力と既存文字の編集を、それぞれ外側タップで閉じ、画面と端末内データを照合する。

**受け入れシナリオ**:

1. **前提** 新規の空の draft、**操作** 外側の空白を1回タップ、**結果** 入力欄・ツールバー・キーボードが閉じ、要素が増えない。
2. **前提** 文字を入力した新規 draft、**操作** 外側の空白を1回タップ、**結果** 未確定文字が破棄され、保存内容と履歴は変わらない。同じタップで次の入力は始まらない。
3. **前提** 既存文字の内容・種類・色を編集中、**操作** 外側をタップ、**結果** 未確定変更が破棄され、元の内容・種類・色・座標が保持される。
4. **前提** 新規入力を外側タップで取り消した、**操作** 改めて空白をタップ、**結果** 通常どおり新しい入力を開始できる。既存要素の編集終了後は従来の選択解除規則に従う。
5. **前提** draft がある、**操作** 外側の既存要素をタップ、**結果** 取り消しだけを行う。そのタップによる選択・移動・削除・新規入力は起きない。
6. **前提** draft がある、**操作** 入力欄内または編集ツールバーを操作、**結果** 編集を継続でき、「完了」は確定、「やめる」は取り消しとして機能する。

### User Story 2 - 入力と保存を意図せず失わない (Priority: P1)

利用者が取り消していない入力は画面の再生成や一時的な focus 変化で失われず、確定した内容の保存失敗は再試行できる。

**優先理由**: 外側タップ以外を誤って取り消し扱いにすると利用者の入力を失う。
**独立した検証**: 入力途中・保存中・保存失敗中で画面を再生成し、内容の保持と保存完了・再試行を確認する。

**受け入れシナリオ**:

1. **前提** 新規または既存の draft、**操作** Activity の再生成、一時停止・再開、再描画、IME を閉じる、**結果** draft の内容・種類・色・世界座標を保持し、確定も取り消しもしない。
2. **前提** 「完了」を押して保存中、**操作** 外側タップまたは画面再生成、**結果** 保存要求が維持され、対象要求の保存完了後に editor が閉じる。
3. **前提** 保存失敗で editor が残っている、**操作** 外側タップまたは画面再生成後に「再試行」、**結果** 失敗中は入力を取り消さず、同じ変更を1回分として保存し、成功後に閉じる。

### Edge Cases

- 取り消しは単一 pointer の短いタップの release で成立する。長押し・drag・複数 pointer・途中キャンセルは draft を破棄しない。
- 入力欄と編集ツールバーを外側タップの対象から除外する。表示倍率・IME・再生成による bounds の変化に追従し、閉じた editor の bounds は次の操作を遮らない。
- 通常のキャンバス chrome は編集時に非表示であり、その旧表示位置はキャンバスとして取り消しを受け付ける。保存状態表示へのタップは running/failed の制約に従う。
- 一般的な focus loss だけで draft を取り消さない。OS の system bars と IME の内部操作はキャンバス外側タップではない。
- 「やめる」は引き続き支援技術・キーボードで到達でき、取り消し後に非表示の入力欄へ focus が残らない。

## Requirements

### Functional Requirements

- **FR-001**: 保存操作により編集が禁止されていないとき、入力欄・編集ツールバーの外側のキャンバスタップで、「やめる」と同じ取り消しを行う。
- **FR-002**: 取り消しは新規要素を作成せず、既存要素の未確定変更を反映せず、保存と Undo/Redo の履歴を変更しない。
- **FR-003**: 取り消しタップを消費し、同じ gesture で次の入力、要素への操作、zoom、その他の操作を実行しない。新規入力の取り消し後の次の空白タップでは入力を開始できる。
- **FR-004**: 取り消しで入力欄の focus、software keyboard、editor toolbar を解除する。「完了」と「やめる」は従来の明示的な確定・取り消し操作として残す。
- **FR-005**: 入力欄内と編集ツールバーは通常どおり操作できる。表示中の bounds を用い、旧 chrome bounds が後の操作を遮らない。
- **FR-006**: focus loss、Activity recreation、configuration/lifecycle transition、再描画、IME 内部 transition のみを取り消しの契機にしない。同じ process の画面再生成では draft を保持する。
- **FR-007**: 保存中・保存失敗中は外側タップと明示的取り消しを無効にし、対象保存要求の完了を待つ。再生成後も既存の保存所有者と retry を利用し、二重に要素を作成しない。
- **FR-008**: タップ以外の外側 gesture は取り消さない。通常のキャンバス操作、TalkBack、編集ツールバーの accessibility action、system back、ボード移動の既存契約を維持する。

### Key Entities

- **draft**: 未確定のテキスト、種類、色、世界座標、編集対象の識別子。保存済み要素とは別のボード単位の編集状態。
- **保存要求**: 明示的な確定に対する保存完了の通知。取り消し対象ではない。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 新規の空・文字あり draft と既存文字編集の外側タップの検証で、意図しない保存・要素作成・次の入力開始が0件。
- **SC-002**: 入力途中・保存中・失敗中の画面再生成と一時停止・再開の検証で、未確定入力の意図しない破棄・確定、二重作成が0件。
- **SC-003**: 外側タップと「やめる」で入力欄・toolbar・入力 focus・IME が解除され、次の有効な空白タップと「完了」から通常どおり入力・保存できる。

## Assumptions

- Issue #71 が委ねた target forwarding は dismiss-only とする。編集時に通常 chrome は非表示のため、表示中の編集ツールバーは操作を維持し、既存要素は取り消しだけを行う。
- process 終了後の未確定 draft 復元、暗黙の保存、toolbar 再設計、gesture architecture 全体の変更は対象外。
- Android 標準の focus・IME・入力 gesture を使う。自由配置上の外側取り消しの判定にだけ既存キャンバスの pointer admission を補う。
