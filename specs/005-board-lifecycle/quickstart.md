# 検証手順: Board Lifecycle

## 事前条件

既存の単一ボードに文字、図形、囲み、矢印、手書きを含むデータを用意する。別の新規インストール状態も用意し、更新時の保持と初回案内を分けて確認する。画面と出力の期待動作は [操作契約](contracts/interaction.md) に従う。

```powershell
git diff --check
```

## 画面とデータの確認

1. 既存アプリを更新し、従来のボードと文字・図形・矢印・手書きが残ることを確認する。
2. 一覧から3件以上のボードを作り、最終編集順、2列の遠景プレビュー、日付表示を確認する。各ボードを開くと内容全体が収まることを確認する。
3. 名前変更、複製、確認を取り消した削除、確定した削除を試し、他のボードと複製元が変わらないことを確認する。最後の1件を削除した場合の空状態も確認する。
4. 保存中に一覧へ戻る/ボードを切り替える操作を試し、内容が失われず別ボードへ入らないことを確認する。再起動後は最後に開いたボードが復元されることを確認する。
5. 新規インストールの最初の空ボードで案内を閉じ、別のボードで自動再表示されないことを確認する。一覧の「使い方」から再表示する。
6. ボード全体と選択範囲を画像で保存、コピー、Android 共有し、プレビューとの一致、背景、余白、選択外の混入がないことを確認する。共有先キャンセル後も元データを照合する。
7. TalkBack で一覧のカード、長押しメニュー、削除確認、案内、共有の操作名と実行可能性を確認する。

実機の視覚的な仕上がりは、利用者の方針に従って後日まとめて確認する。
