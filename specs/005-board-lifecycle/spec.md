## User Scenarios & Testing

### User Story 1 - 複数のボードを安全に使い分ける (Priority: P1)

利用者はボード一覧から新規作成、再開、名前変更、複製、削除を行い、複数の考えを混ぜずに管理できる。

**独立した検証**: 異なる内容のボードを2件作り、各操作と再起動後の一覧・内容を照合する。

**受け入れシナリオ**:

1. **前提** ボードが1件ある、**操作** 一覧の＋から作成する、**結果** 空のボードが開き、元のボードは変わらない。
2. **前提** 内容の異なるボードが複数ある、**操作** 一覧から開いて編集し、アプリを再起動する、**結果** 最後に開いたボードとその内容に戻り、一覧は最終編集順に並ぶ。
3. **前提** 内容のあるボード、**操作** 名前変更または複製する、**結果** 対象だけが変更され、複製は独立した内容を持つ別ボードになる。
4. **前提** 複数のボード、**操作** 1件を削除する、**結果** 確認後にそのボードだけが消え、残りを開ける。

### User Story 2 - 画像で考えを持ち出す (Priority: P2)

利用者はボード全体または選んだ部分をプレビューし、画像を端末へ保存、コピー、Android の共有先へ渡せる。

**独立した検証**: 全体と選択範囲でそれぞれ3つの出力を試し、画像の内容・余白・背景と元データの不変性を確認する。

**受け入れシナリオ**:

1. **前提** 内容のあるボード、**操作** 一覧の長押しから「画像で共有」を選ぶ、**結果** ボード全体のプレビューと3つの出力方法が現れる。
2. **前提** キャンバス上で要素を選択している、**操作** 選択範囲の「画像で共有」を選ぶ、**結果** 対象だけを含むプレビューが現れ、名前付き囲みを選んだ場合は内側の内容も含まれる。
3. **前提** プレビューを確認した、**操作** 保存・コピー・ほかのアプリのいずれかを選ぶ、**結果** 対応する Android の保存先、クリップボード、共有メニューへ画像が渡り、ボードは変わらない。

### User Story 3 - 最初の操作を知る (Priority: P3)

利用者は初めて空のボードを開いた際に基本操作を学べ、後から一覧の「使い方」で同じ案内を見直せる。

**独立した検証**: 初回の空ボード、新たな空ボード、既存ボードで案内の表示回数と再表示を確認する。

**受け入れシナリオ**:

1. **前提** 初めて空のボードを開く、**操作** アプリを起動する、**結果** 「基本の操作」が下部に現れ、「はじめる」で閉じられる。
2. **前提** 案内を閉じている、**操作** 別のボードを作る、**結果** 案内は自動では繰り返されない。
3. **前提** ボード一覧、**操作** 「使い方」を押す、**結果** 基本の操作を再表示できる。

### Edge Cases

- ボードが0件なら一覧を空状態として表示し、新規作成できる。最後のボードを削除しても別のボードを暗黙に作らない。
- 削除は確認を要し、取り消した場合は一覧順と内容を含め何も変えない。削除済みボードの Undo/Redo 履歴は、ほかのボードへ引き継がない。
- 保存中に一覧へ戻る、ボードを切り替える、複製・削除する場合、完了していない編集を失わず、古いボードの保存が別ボードへ入らない。
- 名前が空なら表示上は「無題のボード」とし、同名は許す。名前を変えても最終編集日時は更新する。
- 空ボードまたは空の選択範囲の画像共有はできないことを明示し、空画像を保存・共有しない。
- 出力先の権限不足、保存失敗、共有先のキャンセルでは元データを保ち、利用者に結果を知らせる。

## Requirements

### Functional Requirements

- **FR-001**: 一覧にはボードを2列のカードで示し、遠景の縮小プレビュー、名前、最終編集日を表示する。並びは最終編集日時の降順とし、同時刻なら識別子で安定させる。
- **FR-002**: 一覧からボードを作成・開く。開くときは内容全体が収まる視点とし、空ボードなら中央に「どこでもタップして書く」を表示する。
- **FR-003**: 一覧カードの長押しで、名前を変える、複製、画像で共有、削除、キャンセルを含む下部メニューを開く。各操作対象を明示する。
- **FR-004**: 名前変更は対象のボード名だけを変える。複製は文字、図形、囲み、矢印、手書きと位置・関係を別のボードへ複写し、以後は元と独立して編集できる。
- **FR-005**: 削除は対象名を示して確認した後、そのボードと要素だけを削除する。削除済みボードの操作履歴と最後に開いた位置づけを残さない。
- **FR-006**: ボードごとに内容と最終編集日時を端末内へ保存する。再起動後、最後に開いたボードがまだあればそれを復元し、なければ一覧を表示する。
- **FR-007**: 既に端末内へ保存済みの単一ボードがある利用者は、更新後もその内容を1件のボードとして使える。移行失敗時に既存内容を消さない。
- **FR-008**: 初回の空ボードにだけ「基本の操作」を自動表示し、「はじめる」で閉じた記録を端末内に保存する。一覧の「使い方」から再表示できる。
- **FR-009**: 案内には空白タップで書く、書いたものの長押し移動、空白の長押しで余白を作る、＋からペン・図形・囲み、右上から検索を示す。
- **FR-010**: ボード一覧から全体を、キャンバス上の選択操作から選択範囲を画像共有の対象にできる。選択した要素はすべて含める。選択した囲みには中心が内側にある文字・図形・手書きを加え、矢印は明示的に選択されているか、両端がその囲みの内側にあり接続先も対象に含まれる場合だけ加える。囲みの外へつながる矢印は自動では加えない。
- **FR-011**: 共有前に対象名と出力画像と同じ内容を縮小したプレビューを示し、画像を保存、コピー、ほかのアプリへの3操作を提供する。「ほかのアプリ」は Android の共有メニューを開く。一覧カードの遠景プレビューと異なり、共有画像では本文や手書きを省略しない。
- **FR-012**: 出力画像はキャンバスの暖かい白の不透明背景に、対象の外接範囲から上下左右それぞれ同じ余白を付ける。余白は世界座標で24以上かつ対象の長辺の5%以上とする。位置関係、文字、色、線を保ち、通常は世界座標1単位につき2 px、上限に収める場合も1 px未満には縮小しない。長辺4096 px・総画素16 MPに1 px/単位で収まらない対象は画像化せず、理由を表示する。
- **FR-013**: プレビューと出力は保存済み内容を読み取るだけとし、他ボード、元ボードの要素、座標、関係、Undo/Redo 履歴を変えない。画像は利用者が明示した出力先にだけ渡す。
- **FR-014**: 一覧、下部メニュー、確認、案内、共有の全操作をタッチに加えて支援技術でも識別・実行できるようにする。

### Key Entities

- **ボード**: 一意の識別子、表示名、最終編集日時、要素の集合を持つ。複製後は独立した識別子と要素を持つ。
- **ボード要素**: 文字、図形・囲み、矢印、手書き。所属ボードと位置・関係を保持する。
- **利用状態**: 最後に開いたボードと初回案内を閉じたかどうか。ボードの内容とは別に端末内へ保持する。
- **共有対象**: 全体または選択範囲と、範囲に含める要素。保存済みボードへの参照であり、別のボードではない。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 3件以上のボードで作成、切替、名前変更、複製、削除を行い、再起動後も対象外のボードの内容が全件一致する。
- **SC-002**: 既存の単一ボードを含む端末で更新し、移行前後の文字・図形・矢印・手書きの件数と内容が一致する。
- **SC-003**: 20件のボード一覧を開き、すべてのカードの名前・日付・プレビューが正しい順に表示され、任意のボードを開ける。
- **SC-004**: 全体と選択範囲で保存・コピー・共有した画像を照合し、対象外要素が0件、欠けた対象要素が0件である。
- **SC-005**: 共有とキャンセル、削除確認のキャンセルの前後で元ボードと他ボードの保存データ、Undo/Redo 履歴が一致する。

## Assumptions

- 製品要件は非公開 PRD を authority とし、HTML モックは画面配置と操作感の reference implementation とする。
- アカウント、クラウド同期、バックアップ、外部サービスへの自動アップロードは対象外とする。
- 日付表示は端末のローカル日付を使い、今日なら「今日」、それ以外は「9月21日」の形式を基本とする。
- 共有画像は元の配置を切らず、個別のボード名などのメタデータを付けない。
- 実機の視覚的な確認は、Android 17 エミュレーターで動作を検証した後、ほかの Issue とまとめて行う。
