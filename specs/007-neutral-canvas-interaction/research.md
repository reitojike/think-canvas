- **Decision**: Backは変更ありだけ標準AlertDialogで破棄確認。**Rationale**: PO確認済み。**Alternatives**: 自動Doneは採用しない。outsideはSpec 006を維持。
- **Decision**: text/regionは既存board session、小さいtool/確認識別はrememberSaveable。**Rationale**: [Android state saving](https://developer.android.com/develop/ui/compose/state-saving)のViewModelとsaved-instance-stateの役割に合わせる。**Alternatives**: schema保存・generic lifecycle managerは不要。
- **Decision**: ink blank tapはexitにしない。**Rationale**: Spec 003 FR-003は指1本が描画で、最短strokeと終了が衝突する。**Alternatives**: 独自tap/dot閾値は未承認の描画意味変更。
- **Decision**: [BackHandler](https://developer.android.com/reference/kotlin/androidx/activity/compose/package-summary)と標準dialogを使い、tool exitでpointerInputをcancelする。**Rationale**: 古いUPのcommitを防ぐ。**Alternatives**: gesture全面rewriteは不要。
- dependency追加なし。未解決technical clarificationなし。
- Issue91のIME復帰: [Android公式のwindow/input connection条件](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility#show-reliably)に合わせ、[Compose WindowInfo](https://developer.android.com/reference/kotlin/androidx/compose/ui/platform/WindowInfo)で既存entry/resume要求をone-shot待機する。requestFocus後にframe適用を待ち、window ownerを再確認してからshowする。window focusをeffect keyにせず、Backで意図して隠したIMEをwindow往復だけで再表示しない。独自retry/lifecycle managerや新しい製品判断は導入しない。
- Issue91の接続成立: CI37169491939のoutside復帰timeoutから、window focusと1frameだけではnative InputConnection成立を保証しない。LocalViewのhostに対して標準InputMethodManagerのactive/acceptingTextも取消可能なframe待機で確認し、showは一回だけとする。任意の固定delay、IMEを強制表示するflag、window帰還ごとの再表示、独自retry managerは追加しない。既存Compose keyboard controllerはAndroidXの標準compat経路を使用しており、別controllerへの重複要求で回避しない。
- Issue91のpending失効: LaunchedEffect keyの取消は再composition後になる。native window帰還を再描画前に受ける回帰で、終了済みfieldがFocused=trueとなることを実測した。requestFocus前とframe待機後にlive text/region sessionId、確認状態、searchOpenを照合し、終了・置換・確認中の要求を同期に破棄する。終了時cleanupやIMEを隠すBackの意味は変更しない。
- 同じ位置/対象での編集session置換はtext/regionのsessionId keyで新しいentry要求を開始する。通常の入力/copyではsessionIdを維持するためIMEを再要求しない。window focusはkeyにせず、IME非表示のwindow帰還だけでは再表示しない。
- Issue91の入力制御所有: 上記IMM active/acceptingTextのframe pollは、readonly fieldで成立しない無期限待機を作り得るため置換した。API30以降は標準WindowInsetsControllerのIME-controllability通知を取消可能に待ち、API26〜29はwindow focus/frameと標準Compose keyboard経路を使う。callback/effect取消でlistenerを除去し、dispatch中のlistener一覧変更はpostで避ける。controllabilityはIME表示成功の保証ではなく、hardware keyboard/IME製品による拒否を反復showで覆さない。
- focusとIMEのadmissionは区別する。現在の実在fieldはreadonlyでもwindow復帰後にfocus可能だが、save/ack blockedではその後のIME待機/showを行わない。inputAllowed keyはblocked状態への遷移でpending IMEを取消し、入力可能状態への復帰で既存ownerの要求を再開する。保存所有者やreadOnly属性を変えない。
- 受理済みIME hideと確認遷移は、待機中の入力要求も同期取消する。三ownerのLaunchedEffect Jobをremember内の有限setへ登録し、finallyで除去する。clearEditorFocus、IME優先Back、検索closeの既存hide箇所でJobをcancelし、searchもlive確認guardを照合する。window focus/入力内容を再起動keyに追加しない。[第五checkpoint](https://github.com/reitojike/think-canvas/pull/92#issuecomment-5976244593)のnative RED/GREENで確認した。production window flag・依存・CI・保存処理の追加はない。

- Issue91のlate focus loss: 最終frame中にnative所有を失った要求を完了扱いにすると、window focus非keyのため帰還後に復帰できない。三ownerのfocus要求後の未完了IME段階だけをapp固有の小さいsuspend関数へ分離し、現在session/save admission→window所有→IME control→frame→最終所有を取消可能に照合する。focus/showは各一回のまま、control成立とwindow所有を分離する。generic coordinatorや新しい状態所有者は作らない。legacy control adapterはno-op、modernは標準通知であり、API26〜29 native実行を単体adapterの検証で代替したことを明記する。[第六checkpoint](https://github.com/reitojike/think-canvas/pull/92#issuecomment-5977331918)。
