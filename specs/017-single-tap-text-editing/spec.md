# 機能仕様: テキストの1タップ編集

**Feature Branch**: `codex/issue-111-single-tap-text-editing`
**Created**: 2026-10-15
**Status**: 承認仕様の実装中・未merge
**Input**: [Issue #111](https://github.com/reitojike/think-canvas/issues/111) と2026-10-15のユーザー承認。

## User Scenarios & Testing

### User Story 1 - 既存テキストを1タップで編集する (Priority: P1)

通常時は選択のための追加タップを挟まず、既存テキストへの1タップで編集する。

**優先理由**: 日常の編集開始を2タップから1タップへ減らす。
**独立した検証**: 未選択・単独選択・他の1要素が選択された状態から、本文または見出しを1タップし、対象の編集が1回だけ開き、確定前の保存や履歴変更がないことを確認する。

**受け入れシナリオ**:
1. 未選択または単独選択中のテキストを短くタップすると、その同じテキストの内容・種類・色・位置を持つ編集が1回開く。
2. テキストAを編集中に外側のBをタップすると、既存の確定契約でAを閉じる。同じタップでBの編集を開かず、次の独立したBへのタップで編集する。
3. 保存・acknowledgementのguard中は編集開始を拒否し、既存の編集確定・取消・再試行・Undoを維持する。

### User Story 2 - 複数選択と要素操作を維持する (Priority: P1)

複数選択中は編集を始めず、タップで選択を追加・解除できる。移動・削除・共有へ到達する明示操作を残す。

**優先理由**: 編集の短縮によって空間上の整理操作を失わない。
**独立した検証**: 複数選択に含まれる/含まれないテキストをタップし、選択集合の差分だけが変わることを確認する。長押しメニューの選択、移動grip、削除、共有、長押しドラッグ、投げ縄を確認する。

**受け入れシナリオ**:
1. 2件以上の選択中に未選択テキストをタップすると、その対象だけを追加し、編集中にはならない。
2. 2件以上の選択中に選択済みテキストをタップすると、その対象だけを解除し、編集中にはならない。
3. 選択集合が1件以下になれば通常時の1タップ編集へ戻る。持続する別の複数選択モードは追加しない。
4. テキストの長押しメニューから明示的に選択し、既存の移動grip・削除・共有へ到達できる。長押しドラッグと投げ縄による選択も維持する。

### User Story 3 - 検索と支援技術でも操作結果を一致させる (Priority: P2)

検索移動だけでは編集を始めず、見つけたテキストへの明示タップで編集する。支援技術の操作名は実際の動作を伝える。

**独立した検証**: 検索結果へ移動した時点では入力欄が増えず、その後の通常テキストタップで編集が開くことを確認する。primary actionと選択の明示操作を確認する。

**受け入れシナリオ**:
1. 検索語の入力・前後移動・結果への視点移動だけではテキスト編集を開かない。通常時に対象をタップすると編集する。
2. 通常時のテキストのprimary actionは「編集」とし、複数選択中は対象の状態に応じて「選択に追加」または「選択から外す」とする。動作も同じ分岐に従う。
3. 明示的な選択追加・解除と移動操作へ到達できる。非表示のテキストは操作対象にしない。

### Edge Cases

- 本仕様の通常時は、既存の保存guardにより操作が許可され、他のeditorや作成・ink gestureが操作を所有していない状態を指す。
- 複数選択は既存の選択集合が2件以上の状態とする。検索中も複数選択の追加・解除を優先する。
- 明示的なメニュー「編集」は既存の明示編集として維持し、複数選択中のprimary tapとは区別する。
- Semantic Zoomで隠れたテキストを編集対象へ復活させない。検索一致・選択の既存keepを維持する。
- 外側の確定タップは終了だけに使い、他要素への編集・選択・新規入力へforwardしない。終了後の独立gestureを受け付ける。
- blank tap/double tap、stylus/ink、paletteの外側dismissal、長押し・drag・CANCELは既存の入力所有者と契約を維持する。

## Requirements

### Functional Requirements

- **FR-001**: 通常時の既存テキスト1タップで同じ要素の編集を開始する。先に選択するためのタップは要求しない。
- **FR-002**: 選択が2件以上なら、テキストのprimary tapは追加または解除だけを行い、編集を開始しない。
- **FR-003**: 長押しメニューの明示選択と支援技術の選択追加/解除を通して、単独・複数選択、移動、削除、共有に到達できる。長押しドラッグ・投げ縄を保持する。
- **FR-004**: 検索の視点移動だけでは編集を開始しない。その後のテキスト操作はFR-001/002に従う。
- **FR-005**: 支援技術のprimary action名と動作をFR-001/002に一致させ、対象テキストを取り違えない。非表示対象は操作しない。
- **FR-006**: [Spec006](../006-text-editor-dismissal/spec.md)の外側確定は同じgestureを消費し、別テキストの編集を始めない。次の独立タップから通常操作を受理する。
- **FR-007**: [Spec007](../007-neutral-canvas-interaction/spec.md)の保存guard・acknowledgement・Back・編集確定取消・再試行・lifecycleを維持する。編集開始と選択変更だけでは保存・Undo/Redoを変えない。
- **FR-008**: blank tap/double tap、stylus/ink、作成tool、長押しドラッグ、投げ縄の既存gesture所有権を維持する。
- **FR-009**: 保存済み内容・座標・種類・色を編集開始時に保持し、編集開始の重複による別sessionや要素を作らない。

### Key Entities

- **テキストのprimary action**: 通常時は編集、複数選択中は対象の追加/解除。
- **選択集合**: 既存要素の識別子の集合。2件以上で複数選択として扱う。
- **編集session**: 既存の未確定内容と保存/終了の所有者。新しい保存状態や選択モードは追加しない。

## Success Criteria

- **SC-001**: 通常時の本文・見出し、未選択・単独選択の全対象ケースで、編集開始は1タップ・1sessionとなり、確定前の保存/履歴変更は0件。
- **SC-002**: 複数選択中の追加/解除では対象以外の選択を維持し、編集開始と保存/履歴変更は0件。
- **SC-003**: Aの編集外側でBを1回タップした時点でBの編集開始は0件、次の独立したBタップで1件となる。
- **SC-004**: 長押し・明示選択・投げ縄・検索・支援技術の指定経路に到達でき、操作名と結果の食い違いと同一gestureの二重actionは0件。

## Assumptions と承認記録

- 2026-10-15、ユーザーは通常時の直接編集と複数選択時の追加/解除、長押し等の操作導線、検索移動だけでは編集しないこと、外側確定のfinalize-only、支援技術の名前と動作の一致を承認した。
- 選択集合の件数による既存の状態境界を使い、1件以下に戻った後の別タップは通常時とする。
- 従来の通常1タップ選択は明示選択の操作へ移るため、移動grip等へ入る手順は変わる。長押しドラッグは維持する。
- 新規保存形式、選択mode、gesture framework、editorの見た目の再設計、依存更新、テスト基盤の全面整備は対象外。
- 本specは#111の作業中の承認仕様で、mergeまでは既存のmerge済みspecを暗黙に置き換えない。
